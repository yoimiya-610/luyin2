# 全项目审阅与修复记录 · 1.5.2

本轮从清洁工作区 d3afeab 开始，已在修改前同步远端。审阅范围包含录音采集与编码、会话恢复、试音生命周期、音高与频谱显示、钢琴输出、媒体扫描与导入、分类/重命名/删除、播放队列与状态恢复、导出、权限与项目配置。静态审阅结合现有回归检查；不表示所有设备分支均已实测。

## 已修复的问题

| 优先级 | 触发及影响 | 修复与验证 |
| --- | --- | --- |
| 高 | 麦克风读入失败后，stop 抛出错误，使 CaptureService 把已正常封装的有效录音也作为失败片段删除 | 区分“采集异常”和“封装失败”；保留成功封装且有时长的有效前缀，继续报告中断。使用 AudioRecord Shadow 注入 100 ms PCM 后 ERROR_DEAD_OBJECT，验证 WAV 大小和保存结果；封装失败仍拒绝保存 |
| 中 | 文件重命名导致 URI 改变，但多选集合仍指向旧 URI，后续操作无法找到已选项 | 重命名后同步解析多选集合中的重定向地址；验证地址迁移和刷新 |
| 中 | 两个 Library 实例同时导入，各自读取旧索引后保存，可能覆盖另一份导入；旋转后旧后台任务与新任务可能并存 | 复制和读取元数据在锁外完成，去重与索引合并使用应用内统一修改锁；双线程、不同实例导入验证两条索引都保留 |
| 中 | 文件提供方返回空显示名称时，导入可能产生空白名称；元数据提取器释放失败还会中断已完成的导入 | 空名称使用“导入录音”，释放异常与音频保存分离；提供方测试覆盖空名称 |
| 中 | 试音停止时读取时长抛异常，会跳过麦克风释放和分析边界清理 | 时长读取与释放分别保护，确保清理逻辑继续；模拟异常验证 release 仍调用 |
| 中 | 播放器报错时无条件 play，可能在暂停状态意外开始播放；循环队列全部失效时缺少连续错误上限 | 保持用户暂停意图，连续失败达到队列长度即暂停；就绪后重置错误计数，验证暂停与循环失败边界 |
| 低 | 保存的播放索引为负数时可能导致恢复失败 | 同时限制索引上下界；恢复测试覆盖负数 |
| 中 | 编码器反复返回非数据状态时，continue 跳过输出超时检查，可能长时间卡在收尾 | 把超时检查放到每轮 drain 顶部，所有返回状态都受限制。具体硬件编码器行为仍需设备验证 |

## 已完成的优化

- WAV 每 100 ms 写入时复用 PCM 字节缓冲，减少长录音期间的临时对象与垃圾回收；增加“大块后接小块”测试，防止复用缓冲带入旧样本。
- 波形/声谱图按钮只在显示模式改变时创建背景，避免每秒反复分配 RippleDrawable；验证状态不变时复用同一个背景对象。

## 审阅中的纠正

初步怀疑的“重命名后录音室空指针”在复核后不成立：比较由非空 fingerprint 发起，允许缓存为 null；没有把这一猜测当成修复成果。实际修复的是多选 URI 过期问题。

## 仍需设备验证及后续优化

- 未连接红米 K80 或其他安卓手机，未运行设备模拟器；来电、熄屏省电、蓝牙/耳机、真实编码器和音频焦点、横屏持续采集仍须真机验证。
- 录音停止和部分同步索引写入仍在主线程，极慢存储可能造成界面短暂停顿。迁移到后台需要同时调整服务命令顺序与退出等待，未在这轮做架构重写。
- 声音分析针对单音；多人、强混响、弱基频和和弦的误判需要更多真实音频数据评估，现有合成信号测试不能代表所有声学环境。
- 异常掉电时未正常关闭的当前文件仍可能无法恢复；本次修复只保留能够成功封装的有效录音，不承诺修复损坏容器。

构建、测试数量、签名与安装包校验见 [验证记录](验证记录.md)。
