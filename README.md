# 录音随听

当前版本：**1.2.0**。可用新 APK 直接覆盖安装旧版本，保留原来的导入文件、播放队列和设置。

## 页面与功能分类

界面采用浅色背景、森林绿录音面板、统一线条图标和卡片样式。底部导航固定为四个独立页面，避免在首页堆积全部按钮。

| 页面 | 主要功能 | 次要操作的位置 |
| --- | --- | --- |
| 录音库 | 搜索、按来源筛选、勾选录音、导入 | 右上角选项：扫描、授权文件夹、选择排序；单个片段的更多菜单：导出、重命名、修正来源 |
| 录音室 | 长录音、真实声音波形、暂停和继续、结束保存整组 | 本次已保存片段列表；列表标题旁可导出本次片段 |
| 播放 | 进度、上一段/下一段、连续播放/单曲循环、队列 | “管理队列”保存预设或批量导出；片段更多菜单上下移动或移出 |
| 预设 | 查看和载入已经保存的播放顺序 | 预设更多菜单：追加、导出整组、重命名、删除 |

录音库和预设页保留紧凑的迷你播放器。录音室专注录制，不堆叠播放控件。列表使用原生 ListView，只创建可见行，适合较多录音。

## 录音导出

- **单个片段**：点片段右侧更多菜单 → 导出录音 → 在系统保存窗口中选择位置。按原音频格式复制，不转码。
- **所选片段**：按希望的先后顺序勾选 → 选项 → 导出所选录音。
- **播放队列**：播放页 → 管理队列 → 导出整个队列。
- **整组预设**：预设页 → 选中预设 → 导出整组录音。
- **本次长录音**：录音室 → 本次录音片段标题旁导出图标，只导出已经保存的片段。

一次导出一段时生成独立音频；多段时生成 ZIP 文件，里面按 `001-原名称.m4a`、`002-原名称.m4a` 等顺序编号。重复加入队列的片段会按出现次数分别导出；超过 999 段时会增加编号位数，仍可按文件名排序。各段保持原始字节和音频格式，原文件不会被删除。

导出前通过 Android 的 `ACTION_CREATE_DOCUMENT` 系统窗口选择保存位置，不额外申请整个存储盘的管理权限。取消保存不会开始复制。如果读取权限失效、原文件已移动或磁盘空间不足，会报告失败并尝试清理不完整文件；此时原始录音保留。导出时顶部显示状态提示，仍可切换页面和控制录音；旋转屏幕不会重复启动导出。大文件导出期间请保持应用运行，进程被强制结束可能留下不完整的导出文件，下次打开时会提示重新导出。

## 长录音、预设队列与重命名

### 长录音

1. 底部切换到 **录音室 → 开始长录音**，允许麦克风权限。建议允许通知，以使用通知栏里的暂停、继续和结束按钮。
2. 点击 **暂停并保存片段**，会立刻关闭并保存这一段音频；暂停期间不录制，也不计入录音时长。
3. 点击 **继续录制下一段**，开始下一段；可以反复暂停、继续。
4. 点击 **结束并保存整组队列**，正在录制的最后一段也会保存，本次全部有效片段会按录制顺序自动保存成一个预设队列。不会覆盖原来的播放队列。
5. 底部切换到 **预设**，选择本次长录音，载入或直接播放。也可重命名这个预设。

录音室的“声音波形”使用 `MediaRecorder.getMaxAmplitude()` 的真实麦克风峰值，每 100 ms 采样，显示最近约 12 秒的有效录音振幅包络。暂停时停止采样并保留已有波形，继续时追加新样本；开始新会话时清空。波形不是模拟动画，也不是身份识别意义上的声纹或完整频谱。波形只保留在当前进程内，不作为音频文件的永久分析数据保存。

新录音单独显示为 **本机录音**。红米 K80 上的实际文件保存到共享目录 `Recordings/录音随听/`，格式为 AAC 编码的 M4A，单声道、44.1 kHz、128 kbps，约每小时 58 MB。Android 10/11 的兼容目录为 `Music/录音随听/`。

默认软件内名称为 **手机本地日期-当天递增数字**，例如 `20261105-1`、`20261105-2`；实际文件保留 `.m4a` 扩展名。当天多次长录音共用递增编号，跨日的新片段使用新日期。极短、失败的录音不会生成有效片段，已使用的编号不回退，因此可能出现跳号。

录音使用带麦克风类型的前台服务，并在录制期间保持唤醒锁，支持熄屏及返回首页后继续录制。长录音没有设置总时长上限，但受手机储存空间、供电及系统策略影响；单段接近 1 GiB 时自动分段后继续。自动分段可能存在很短的切换间隔。如麦克风被来电或其他应用占用，会尝试保存当前段并暂停，须确认后继续。

录制开始和继续时会暂停本应用播放器，避免将扬声器声音录入；在软件内播放前应先暂停录音。

每个已完成片段及会话状态会写入本地索引。若应用进程意外结束，下次打开会尝试恢复有效片段并生成预设。**尚未正常关闭的当前 M4A 片段可能无法恢复**；已保存的其他片段会独立保留。此恢复逻辑尚未经过 K80 真机断电测试。

### 预设队列

- 播放页 **管理队列 → 保存为预设**，或预设页 **保存当前**：将当前播放队列按原顺序保存为一个命名预设。
- 底部 **预设**：可载入、载入并播放、追加到当前队尾、导出整组、重命名或删除预设。
- 载入后可上下移动片段，再保存为新的预设。删除预设只移除列表，不删除音频文件。
- 每次正常结束长录音都会自动保存一个独立预设；没有有效片段时不创建空预设。异常恢复重复执行时使用相同的会话标识，不重复创建预设。

### 重命名

录音库中点击录音后选择 **重命名**，或长按名称；播放队列中也可长按名称重命名。重命名会同步软件内当前队列及已保存预设中的引用。

- **修改文件名**：真正修改原文件，保留原扩展名。本应用新录制和导入的文件可直接修改；来自其他应用的媒体文件可能需要系统确认写入授权。
- **仅软件内名称**：修改本软件的显示名称，不改动原文件，适用于只读目录或不支持重命名的文件提供方。
- 如果旧的文件夹授权只有读取权限，可重新通过 **授权文件夹** 申请读写权限；若系统仍不允许，可使用软件内名称。

为红米 K80 的本地录音整理与连续播放制作的原生 Android 应用。最低 Android 10，目标 Android 15，不申请 INTERNET 联网权限，不上传音频。

## 安装使用

安装包：`output/录音随听.apk`。这是本地调试签名版本，可传到手机后点击安装，按系统提示允许该来源安装应用。

1. 打开“录音随听”，在录音库右上角选项选择 **扫描本地录音**，允许“音乐和音频”权限。后续每次进入应用自动重新扫描。
2. 录音库按 **本机录音 / 录音机 / 通话录音 / 其他音频** 区分。来源依据目录和 MediaStore 的所属应用判断；无法确认的音频放入“其他音频”。片段更多菜单可手动修正来源。
3. 按要听的先后顺序勾选文件，点击 **选项 → 将所选加入队尾** 或 **用所选替换队列并播放**。
4. 在播放队列片段的更多菜单中用 **上移 / 下移** 调整顺序，点击名称立即播放该段，支持从队列移除，不删除原文件。
5. 播放器的 **顺序播放** 按钮可切换成 **单曲循环**。顺序模式播完最后一首停止；循环模式重复当前一首。支持进度拖动、上一首、下一首、通知栏与锁屏控制。

### 红米 / HyperOS 录音访问限制

自动扫描范围是 Android 系统媒体库中本应用可读取的音频，不能保证无授权读取手机上的每一个文件。

- 共享录音文件夹（例如 `MIUI/sound_recorder`）：可自动识别，也可用 **授权文件夹** 补充扫描。授权时指定录音来源，下次扫描会记住。
- 通话录音目录（例如 `MIUI/sound_recorder/call_rec`）：单独归类，优先于普通录音机分类。
- `Recordings/` 是通用目录，不能仅凭该名称断定是小米录音机产生的文件。
- 录音机私有目录，如 `Android/data/com.android.soundrecorder/files`：受 Android 限制，普通第三方应用无法直接读取，也不能通过常规文件夹授权绕过。请在系统录音机选中录音 → 分享 → **录音随听**；或先导出到共享文件夹，再授权该文件夹。
- 文件导入和分享导入均会复制到本应用内部存储，使用 SHA-256 避免重复保存相同内容。卸载应用会删除这些副本，原始录音不会被更改。

如果长时间锁屏后播放被 HyperOS 终止，可在“设置 → 应用设置 → 录音随听 → 省电策略”中选择“无限制”（菜单名称随系统版本而异）。

连续播放使用 Media3 ExoPlayer 同一个播放队列自动切换，无需逐首点击。文件自带的头尾静音会保留；不同文件格式、编码器延迟及设备解码器可能影响衔接，尚未在 K80 实机验证逐采样无缝效果。

## 构建

依赖 JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle 8.11.1。Android Gradle Plugin 8.9.2；Media3 1.8.0。Android JVM 测试使用 JUnit 4.13.2 和 Robolectric 4.14.1，首次运行需下载测试依赖及 Android API 35 测试运行库。

本机已将开发工具放入 `.toolchain/`。在本文件夹运行：

```powershell
.\scripts\test.ps1
.\scripts\build.ps1
```

构建脚本执行 `assembleDebug lintDebug testDebugUnitTest`，然后将 APK 复制到 `output/录音随听.apk`。调试签名位于 `.toolchain/debug.keystore`；后续更新同一安装必须保留同一签名。正式分发前应使用自己的发布签名。

源码入口：`app/src/main/java/cn/luyin/player/MainActivity.java`。扫描和导入：`Library.java`。后台播放：`PlaybackService.java`。后台录音：`CaptureService.java`。波形：`WaveformBuffer.java` / `WaveformView.java`。导出：`RecordingExporter.java` / `ExportFiles.java`。

`scripts/test.ps1` 检查来源、日期编号、分段状态、波形缓冲，以及导出字节完整性、重复片段和超过 999 段的 ZIP 排序。`app/src/test/` 使用 Robolectric 验证 Android 页面导航、页面恢复和 ContentResolver 导出；这些 JVM 测试不等于手机硬件或 GPU 渲染测试。

## 验收建议

- 在 K80 上切换四个页面，检查功能分类、字体放大、横屏和软键盘收起后的布局；确认长录音不会因页面切换而停止。
- 录音室对麦克风说话后保持安静，检查波形随实际音量变化；暂停时冻结，继续时追加，开始新录音时清空。
- 分别导出一段录音、多个勾选片段、含重复项的播放队列和整组预设，核对音频可播放、ZIP 中顺序与原字节一致。
- 取消系统保存窗口、撤回源文件权限、模拟空间不足，检查错误提示和原文件保留。

- 连续录制三段，每段 5 秒以上，中间暂停；确认暂停后立即可见独立录音，结束后自动出现顺序正确的预设，软件内默认名为日期编号。
- 在同一天开启第二次长录音，确认编号继续递增；跨日新段确认使用新日期。
- 在录制中、暂停中分别结束会话；测试短于 1 秒的片段、拒绝麦克风权限、关闭系统麦克风开关及空间不足。
- 熄屏录制、从最近任务列表划走应用、通知栏暂停/继续/结束；检查录制时长不包含暂停时间。
- 保存两个不同的手动预设，重开应用后分别载入；重命名录音后检查所有预设仍可播放，重命名预设后检查标题持久保存。
- 在已保存多段后终止应用进程，重开检查已完成片段与预设恢复；对未完成的当前段不作可恢复保证。

- K80 上分别准备录音机录音、通话录音和普通音乐，核对分类；核对未索引文件、分享导入和文件夹授权。
- 选 A、C、B 三段录音，检查队列为 A→C→B；移动顺序、删除当前项及重复加入同一项后继续播放。
- 播放两段短录音，确认自动切换且最后停止；打开单曲循环，确认当前段重复。
- 锁屏十分钟、切换应用、耳机拔出、来电与音频焦点抢占，检查后台与暂停行为。
- 关闭再打开应用，确认队列、循环设置和播放位置恢复；原文件被删除或权限撤回时检查提示。

目前的自动检查不能替代实机测试，尤其是 HyperOS 私有目录、后台省电策略和文件编码差异。
